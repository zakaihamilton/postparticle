# Validation and guardrails

Repnix was audited against the initialized Next.js application, and its read-only setup plan was reviewed. This project intentionally requires TypeScript, ESLint, Prettier, Vitest, JSX accessibility rules, and Knip. Suggested duplication and coverage tooling remain optional rather than adding overlapping checks without a project policy.

`npm run health` runs the configured required providers through repnix. CI also runs the production build and browser workflows. Browser tests check the welcome/login separation, authorized project selection, draft/public boundaries, article tags, revisions, unpublishing, uploads, asset metadata, JSON publication, responsive layout, themes, reduced motion, interactive welcome-page publishing, custom dropdown keyboard selection/dismissal/arrow spacing, disabled viewer controls, unsaved-navigation confirmation, read-only fields during saves, draft retention after failed saves, upload finalization retry/discard, and initial website HTML/SEO. Unit tests cover storage pagination, private ACLs, multipart operations, session expiry/revocation, roles, media deletion, validation, unsafe Markdown, malformed media literals, schemaless JSON field names, and fault-injected multipart/checkpoint/sealing/cleanup recovery.

Tests use temporary local filesystem storage or mocked SDK responses. They do not prove real DigitalOcean compatibility, CORS, public ACL delivery, or deployment WAF configuration. Checkpoint tests cover pruning, preservation of the previous valid generation, fallback from a corrupt newest generation, and unchanged event history. Upload tests cover the six accepted signatures, truncated and mismatched content, rejection cleanup, and transient finalization recovery. Browser tests assert the storage description and verify that a 415 upload rejection does not offer “Retry finalization.” `npm run storage:verify` uses actual configured credentials and creates temporary verification objects; it checks private JSON round trips, full listings, and forced marker pagination, then removes its objects. Use development buckets and follow this with a deployed upload/publish test.

Run `npm audit` when updating dependencies. Production dependencies and development-tool advisories should be evaluated separately; do not downgrade Next.js or disable guardrails merely to hide an advisory. Record unresolved dependency advisories in release notes.

The 2026-10-05 dependency audit found no production advisories and six high-severity development-tool findings through `braces`/`micromatch` in the Next.js lint plugin and repnix. The GitHub advisory lists no patched `braces` release. npm's suggested `eslint-config-next@14.2.35` fix is a semver-major downgrade from this Next.js 16 project, so do not apply it. Keep the current guardrails, keep glob patterns repository-controlled, and refresh the audit when dependencies change or an upstream fix becomes available. See [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
